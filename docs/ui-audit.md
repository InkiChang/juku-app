# UI Audit

## 设计输入

本次原型同时参考现有 Flutter App 和后端内嵌 Web：

- Flutter：首页榜单、站源切换、剧库分页、详情分集、播放器、追剧、我的、服务器设置。
- Web：搜索、筛选排序、VIP 状态、下载任务、用户管理、个人记录、Emby 和播放资源设置。
- 后端接口：维持现有 `/api/ui/*` 与 `/api/emby/*`，本仓库只重构客户端表现层。

## 设计决策

### Context

目标用户是已经有观看习惯的回访用户，第一任务是继续观看，第二任务是快速发现新剧。首页因此将“继续观看”放在首屏第一视觉层，榜单作为第二层内容。

### UX 结构

- 底部四 Tab：首页、剧库、追剧、我的；下载从剧库任务入口进入，避免把高频观看路径分散成五个同等入口。
- 所有主要动作都放在底部拇指区或弹层底部：继续播放、追剧、保存服务器设置。
- 详情使用底部弹层，保持用户在剧库上下文中；播放器使用独立深色弹层，保证媒体区域集中。
- 剧库默认提供搜索、站源、分类、排序和 VIP 状态；不把筛选藏在多层菜单中。
- 加载、空态、错误和同步状态都预留明确位置。

### Visual system

- 60% 深色中性背景，30% 暗色表面层，10% 橙色强调。
- 8pt 网格为主，使用 4/8/12/16/20/24/28/32 间距。
- 单一系统无衬线字体，四档主要字号，两个字重。
- 卡片圆角控制在 8px 以内；按钮优先使用熟悉的图标和短文本。
- 使用真实剧库海报作为内容信号，不使用装饰性渐变或悬浮光球。

### Emotion and polish

- 继续观看卡片把进度、集数和剩余时间放在同一视觉组内。
- 完成同步、保存设置、加入追剧使用轻量 Toast 反馈。
- 播放器保留画质、倍速、选集等高频操作，避免用户反复离开播放页面。
- 所有点击目标不小于 44px，次要信息使用降阶颜色而不是缩小到难以阅读。

## 页面覆盖

| 页面 | 原有元素 | 原型处理 |
| --- | --- | --- |
| 首页 | 榜单、站源、更新、继续观看 | 首屏继续观看 + 横向榜单 |
| 剧库 | 搜索、分页、分类、排序、VIP、播放 | 直接展示搜索和筛选，三列海报网格 |
| 详情 | 简介、标签、集数、追剧、播放 | 底部弹层，选集和主操作固定在末端 |
| 播放器 | HLS/MP4、集数、进度、倍速、画质 | 黑色媒体弹层，媒体操作集中 |
| 追剧 | 在看、想看、已看、进度 | 分段控件 + 续播列表 |
| 下载 | 任务、进度、状态、容量 | 任务摘要 + 分组列表 |
| 我的 | 账号、记录、设置、关于 | 账号状态优先，设置按任务分组 |
| 设置 | 服务器、原始媒体、自动下一集 | 明确说明本地后端和域名切换 |

## 审查入口

启动前端开发服务器后打开：

```text
http://localhost:5173/design-review.html
```

该页面是静态原型，不会请求后端，也不会修改账号、Cookie 或任务数据。
